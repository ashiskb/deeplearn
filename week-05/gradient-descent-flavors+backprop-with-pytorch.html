Flavors of Gradient Descent + Backprop with PyTorch Compute Framework

Ashis Kumer Biswas, Ph.D.

Let’s learn 3 flavors of Gradient Descent

The flavors are:

  1. Full-Batch Gradient Descent
  2. Stochastic Gradient Descent
  3. Mini-batch Gradient Descent
  • Here, we are going to tackle a tiny linear-regression problem for all three methods
    • and the three methods change only how many training samples are used before each parameter gets the update.

A simple regression model

Suppose we want to learn:

\[ \hat y = wx+b \]

from a small dataset.

1. Full-Batch Gradient Descent

Use all training samples to calculate the gradient, then update the parameters once.

import numpy as np

# Dataset: y = 2x + 1
X = np.array([1, 2, 3, 4], dtype=float)
y = np.array([3, 5, 7, 9], dtype=float)

#parameters to learn are: w and b
w = 0.0
b = 0.0

#hyper-parameters
lr = 0.01 #learning rate
num_epochs = 1000 #number of desired epochs to run

#this loop runs `num_epochs` times
for epoch in range(num_epochs):

    # predictions for ALL samples.
    # Analogy: forward pass
    y_pred = w * X + b

    # gradients using ALL samples
    dw = np.mean(2 * X * (y_pred - y))
    db = np.mean(2 * (y_pred - y))

    # one update per epoch
    w = w - lr * dw
    b = b - lr * db

print('Done with training')
print(f"Learned parameters: \nw = {w}")
print(f"b = {b}")
Done with training
Learned parameters: 
w = 2.0048610156782556
b = 0.9857080211211781

The important idea is:

4 samples → calculate gradient → update once

So with 4 samples:

\[ \boxed{\text{1 update per epoch}} \]

2. Stochastic Gradient Descent (SGD)

Use one training sample at a time, calculate its gradient, and immediately update the parameters.

import numpy as np

X = np.array([1, 2, 3, 4], dtype=float)
y = np.array([3, 5, 7, 9], dtype=float)

#parameters to learn are: w and b
w = 0.0
b = 0.0

#hyper-parameters
lr = 0.01 #learning rate
num_epochs = 1000 #number of desired epochs to run

#this loop runs `num_epochs` times

for epoch in range(num_epochs):

    # shuffle the data
    indices = np.random.permutation(len(X))

    #this loop ensures picking each and 
    #      every sample from the training set
    for i in indices: 

        # prediction for ONE sample
        # Analogy: the forward pass
        y_pred = w * X[i] + b

        # gradient from ONE sample
        dw = 2 * X[i] * (y_pred - y[i])
        db = 2 * (y_pred - y[i])

        # update immediately
        w = w - lr * dw
        b = b - lr * db

print('Done with training')
print(f"Learned parameters: \nw = {w}")
print(f"b = {b}")
Done with training
Learned parameters: 
w = 2.000000326531718
b = 0.9999990025216735

Now the process is:

sample 1 → gradient → update
sample 3 → gradient → update
sample 2 → gradient → update
sample 4 → gradient → update
1 epoch completed
sample 1 → gradient → update
sample 4 → gradient → update
sample 2 → gradient → update
sample 3 → gradient → update
Another epoch completed
...
...
1000 epochs completed.

Thus, with 4 samples:

\[ \boxed{\text{4 updates per epoch}} \]

This is why SGD tends to have a somewhat noisy/zig-zagging optimization path.

3. Mini-Batch Gradient Descent

Here, divide the training data into small manageable size batches. Then, calculate the gradient for each batch and update parameters once per batch.

For example, let batch_size = 2.

import numpy as np

X = np.array([1, 2, 3, 4], dtype=float)
y = np.array([3, 5, 7, 9], dtype=float)

#parameters to learn are: w and b
w = 0.0
b = 0.0

#hyper-parameters
lr = 0.01 #learning rate
num_epochs = 1000 #number of desired epochs to run
batch_size = 2 #batch size 


#this loop runs `num_epochs` times
for epoch in range(num_epochs):

    # shuffle data
    indices = np.random.permutation(len(X))
    X_shuffled = X[indices]
    y_shuffled = y[indices]

    #this following loop creates batches of data samples
    # and make sure the entire training set is divided into
    #  equal sized batches. 
    for start in range(0, len(X), batch_size):

        X_batch = X_shuffled[start:start + batch_size]
        y_batch = y_shuffled[start:start + batch_size]

        # predictions for the batch
        # Analogy: forward propagation
        y_pred = w * X_batch + b

        # gradients averaged over the batch
        dw = np.mean(2 * X_batch * (y_pred - y_batch))
        db = np.mean(2 * (y_pred - y_batch))

        # one update per batch
        w = w - lr * dw
        b = b - lr * db

print('Done with training')
print(f"Learned parameters: \nw = {w}")
print(f"b = {b}")
Done with training
Learned parameters: 
w = 2.0002238845118687
b = 0.9993399630343945

With four samples and batch_size=2:

samples 1,3 → gradient → update
samples 2,4 → gradient → update
1 epoch completed
samples 2,3 → gradient → update
samples 1,4 → gradient → update
another epoch completed
samples 1,2 → gradient → update
samples 3,4 → gradient → update
another epoch completed
...
...
1000 epochs completed.

Thus:

\[ \boxed{\text{2 updates per epoch}} \]

The key distinction between the 3 flavors of gradient descent:

Pseudocodes to make sense:

# Full-batch
gradient = gradient_from(all_samples)
update_parameters()

# Stochastic
for a_sample in data:
    gradient = gradient_from(a_sample)
    update_parameters()

# Mini-batch
for a_batch in [data divided into equal sized batches]:
    gradient = gradient_from(a_batch)
    update_parameters()

Note on Full-batch and Stochastic Gradient Descent

  • There is a big difference between these two extreme flavors of gradient descent.
    • The difference comes from how accurately each method estimates the direction of steepest descent.

For a dataset with \(N\) samples, the full-batch gradient is

\[ \nabla L(w)=\frac{1}{N}\sum_{i=1}^{N}\nabla L_i(w) \]

so every update uses the average opinion of all samples. Individual samples may pull the weights in different directions, but much of that variation cancels out. Therefore, for a fixed dataset and learning rate, the update direction is relatively stable and deterministic:

\[ w_{t+1}=w_t-\eta\nabla L(w_t) \]

That gives the smoother trajectory in the first figure.

However, with SGD, we randomly select just one sample:

\[ w_{t+1}=w_t-\eta\nabla L_i(w_t) \]

That sample’s gradient may point somewhat differently from the gradient of the entire dataset. Then the next randomly selected sample may point another way. So SGD behaves approximately like

\[ \text{SGD gradient} = \text{true full gradient} + \text{noise} \]

which creates the zig-zagging behavior:

Intuition: imagine finding directions to a destination, say the Ball Arena Stadium starting from our classroom.

Full-batch GD asks everyone in the class and averages their answers before taking one step. On the other hand, SGD asks one randomly selected student, takes a step, then asks another student. The general direction may still be correct, but the path may wander a lot on the way to the Ball Arena.

This does not mean SGD is bad. The noise can actually be beneficial in deep learning because it may help the optimizer move through flat regions or avoid some undesirable local behavior. As training progresses, we often reduce the learning rate so those oscillations become smaller. More on this in later lectures; so stay tuned!

The three methods therefore form a nice continuum:

\[ \boxed{\text{SGD: noisy}} \quad\longrightarrow\quad \boxed{\text{Mini-batch: moderately noisy}} \quad\longrightarrow\quad \boxed{\text{Full-batch: smooth}} \]

Full-batch follows the average gradient of the whole dataset;

SGD follows an individual sample’s gradient, so its direction changes from sample to sample.**

Practical Notes on the 3 flavors

  • In modern deep learning, mini-batch gradient descent is overwhelmingly the practical choice because it combines reasonably stable gradient estimates with efficient GPU computation.
    • What PyTorch typically calls using an optimizer such as torch.optim.SGD with a DataLoader(batch_size=32) is, technically, mini-batch SGD.

Create tensor _like other tensor

  • All the tensor initialization functions above has a version *_like to create another tensor filled with values corresponding to the function, but with the same size as the input (other) tensor.
    • torch.ones_like(input) – returns a tensor filled with the scalar value 1, with the same size as input tensor.
    • torch.zeros_like(input) – returns a tensor filled with the scalar value 0, with the same size as input tensor.
    • torch.rand_like(input) – returns a tensor with the same size as input tensor that is filled with random numbers from a uniform distribution on the interval [0,1).
    • torch.randn_like(input) – returns a tensor with the same size as input that is filled with random numbers from a normal distribution \(\mathcal{N}(0, 1)\).

Automatic differentiation

  • From: https://pytorch.org/tutorials/beginner/blitz/autograd_tutorial.html
  • Now that you have learned how to use PyTorch Tensors you will learn how we can use PyTorch for automatic differentiation.
  • The autograd package in PyTorch provides automatic differentiation for all operations on Tensors.
    • It is a define-by-run framework, which means that your backprop is defined by how your code is run, and that every single iteration can be different.
  • To allow PyTorch to keep track of operations for automatic differentiation, we need to set requires_grad as True for a Tensor.
    • Autograd will then start to track all operations on the Tensor.
    • When you finish your computation you can call .backward() and have all the gradients computed automatically.
    • The gradient for this tensor will be accumulated into the .grad attribute.
  • To stop a tensor from tracking history, you can call .detach() to detach it from the computation history, and to prevent future computation from being tracked.
  • To prevent tracking history (and using memory), you can also wrap the code block in with torch.no_grad():. This can be particularly helpful when evaluating a model because the model may have trainable parameters with requires_grad=True, but for which we don’t need the gradients.
  • There’s one more class which is very important for autograd implementation - a Function.
    • Tensor and Function are interconnected and build up an acyclic graph that encodes a complete history of computation. Each tensor has a .grad_fn attribute that references a Function that has created the Tensor (except for Tensors created by the user - their grad_fn is None).
  • If you want to compute the derivatives, you can call .backward() on a Tensor.
    • If Tensor is a scalar (i.e. it holds a one element data), you don’t need to specify any arguments to backward(),
    • However if it has more elements, you need to specify a gradient argument that is a tensor of matching shape.

Let’s verify if the gradient, \(\frac{\partial t}{\partial x}\) is correct

  • Given, \(x = \begin{pmatrix}x_{00} & x_{01}\\ x_{10}& x_{11}\\ x_{20} & x_{21}\end{pmatrix} \in \mathbb{R}^{3\times 2}\)

  • \(t = \sum_i z_i\)

  • \(z_i = y_i^2 + 1\)

  • \(y_i = x_i + 5\)

Now, gradient of t with respect to x is –

\[ \nabla_x t = \nabla_z t \nabla_y z \nabla_x y \] where, \[ \nabla_x t = \begin{pmatrix} \frac{\partial t}{\partial x_{00}} & \frac{\partial t}{\partial x_{01}}\\ \frac{\partial t}{\partial x_{10}} & \frac{\partial t}{\partial x_{11}}\\ \frac{\partial t}{\partial x_{20}} & \frac{\partial t}{\partial x_{21}}\\ \end{pmatrix} \] and, \(y\in \mathbb{R}^{3\times 2}, x \in \mathbb{R}^{3\times 2}\) \[ \nabla_x y = \begin{pmatrix} \frac{\partial y_{00}}{\partial x_{00}} & \frac{\partial y_{01}}{\partial x_{01}}\\ \frac{\partial y_{10}}{\partial x_{10}} & \frac{\partial y_{11}}{\partial x_{11}}\\ \frac{\partial y_{20}}{\partial x_{20}} & \frac{\partial y_{21}}{\partial x_{21}}\\ \end{pmatrix}= \begin{pmatrix} 1 & 1\\ 1 & 1\\ 1 & 1 \end{pmatrix} \]

and, \(z\in \mathbb{R}^{3\times 2}, y \in \mathbb{R}^{3\times 2}\)

\[ \nabla_y z = \begin{pmatrix} \frac{\partial z_{00}}{\partial y_{00}} & \frac{\partial z_{01}}{\partial y_{01}}\\ \frac{\partial z_{10}}{\partial y_{10}} & \frac{\partial z_{11}}{\partial y_{11}}\\ \frac{\partial z_{20}}{\partial y_{20}} & \frac{\partial z_{21}}{\partial y_{21}}\\ \end{pmatrix} = \begin{pmatrix}2y_{00} & 2y_{01}\\ 2y_{10} & 2y_{11}\\ 2y_{20} & 2y_{21}\\ \end{pmatrix} \]

and, \[ \nabla_z t = \begin{pmatrix} \frac{\partial t}{\partial z_{00}} & \frac{\partial t}{\partial z_{01}}\\ \frac{\partial t}{\partial z_{10}} & \frac{\partial t}{\partial z_{11}}\\ \frac{\partial t}{\partial z_{20}} & \frac{\partial t}{\partial z_{21}}\\ \end{pmatrix} = \begin{pmatrix}1 & 1\\ 1 & 1\\ 1 & 1 \end{pmatrix} \]

\[ \begin{eqnarray} \nonumber \nabla_x t &=& \nabla_z t \nabla_y z \nabla_x y\\ &=& \begin{pmatrix}1 & 1\\ 1 & 1\\ 1 & 1 \end{pmatrix}\begin{pmatrix}2y_{00} & 2y_{01}\\ 2y_{10} & 2y_{11}\\ 2y_{20} & 2y_{21}\\ \end{pmatrix}\begin{pmatrix} 1 & 1\\ 1 & 1\\ 1 & 1 \end{pmatrix}\\ &=& \begin{pmatrix}2y_{00} & 2y_{01}\\ 2y_{10} & 2y_{11}\\ 2y_{20} & 2y_{21}\\ \end{pmatrix}\quad \text{element wise multiplication} \end{eqnarray} \]

  • At x = 1, y = 6, \(\frac{\partial t}{\partial x_i} = 12\)
    • That is, at \(x = \begin{pmatrix}1 & 1\\ 1 & 1\\1 & 1\end{pmatrix}\)
      • \(y = \begin{pmatrix}6 & 6\\ 6 & 6\\6 & 6\end{pmatrix}\)
      • Therefore, \(\nabla_x t = \begin{pmatrix}12 & 12\\ 12 & 12\\ 12 & 12\\ \end{pmatrix}\)

import torch

learning_rate = 0.01

w = torch.tensor([1.], requires_grad=True)
b = torch.tensor([1.], requires_grad=True)

print(f'Initially,\nw = {w.item()}, b = {b.item()}')

#dataset 
x = torch.randn([20, 1])
y = 3*x - 2 #ground truth



for i in range(10):
    y_hat = w*x + b #predict

    loss = torch.sum((y_hat - y)**2) #compute loss
  
    loss.backward() #calculate gradient
  
    with torch.no_grad(): #omit gradient tracking history
        w -= learning_rate * w.grad
        b -= learning_rate * b.grad
    
    w.grad.zero_()
    b.grad.zero_()

print("\nFinal:")
print("w =", w.item())
print("b =", b.item())

And, we are now ready to push it to a GPU

import torch

# Device
device = torch.device("cuda:0" if torch.cuda.is_available() else "cpu")

# Reproducibility
torch.manual_seed(42)

learning_rate = 0.01
N = 100
epochs = 200

# --------------------------------------------------
# Learnable parameters
# --------------------------------------------------
w = torch.rand((), requires_grad=True, device=device)
b = torch.ones((), requires_grad=True, device=device)

# --------------------------------------------------
# Dataset: y = 3x - 2
# --------------------------------------------------
x = torch.randn(N, device=device)
y = 3 * x - 2

# --------------------------------------------------
# Training
# --------------------------------------------------
for epoch in range(epochs):

    # Forward pass
    y_hat = w * x + b

    # Mean Squared Error
    loss = torch.mean((y_hat - y) ** 2)

    # Compute gradients
    loss.backward()

    # Gradient descent update
    with torch.no_grad():
        w -= learning_rate * w.grad
        b -= learning_rate * b.grad

    # IMPORTANT: clear accumulated gradients
    w.grad.zero_()
    b.grad.zero_()

    if epoch % 20 == 0:
        print(
            f"Epoch {epoch:3d}: "
            f"loss={loss.item():.4f}, "
            f"w={w.item():.4f}, "
            f"b={b.item():.4f}"
        )

print("\nFinal:")
print("w =", w.item())
print("b =", b.item())
